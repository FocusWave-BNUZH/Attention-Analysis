## 两个硬件版本与默认分支的真实关系

默认分支内 `runtime/nir-formal/config.yaml` 仍标0.2.0早期AMD运行包，缺少AMD/NVIDIA第8版完整最终引擎与恢复核心。因此不能为了分支数量把默认分支当作三个生产版本的全集。AMD与NVIDIA第8版源码对比有27项源码/配置/文档差异；关键变动为后端初始化、记录执行后端/提供者、恢复身份约束及执行配置，测量适配器的差异主要是注释。这个源码核对不替代跨硬件真实数据等价性验证。

`nvidia-cuda-v8` 根README和旧根指令混入AMD/旧默认分支定位，和实际最终引擎、配置、运行包说明不一致。本轮仅纠正导航事实；安装、最终数据流、模型约束、恢复校验继续指向该分支已有 `runtime/nir-formal/README.md` 与 `INSTALL.md`。

默认分支没有NVIDIA可见光面部运行脚本 `scripts/face_formal_cuda.py`，现行启动器走AMD后端，因此暂不能把rgb-nvidia当作已完整吸收。rgb-amd另有默认分支缺少的流式工作器和共享解码实验，归档必须保存完整版本而不是挑两份文件。

可收敛目标为4条有直接入口作用的分支：当前正式下游默认分支、AMD近红外第8版、NVIDIA近红外第8版、NVIDIA可见光生产。旧nvidia-cuda、rgb-amd和七算法对比分支适合作完整固定历史版本；这不代表已证明全部重复或删除其本机生产资产。本轮不实施这三项远端归档/删除。
